# Revision-guarded text-input insertion

**wsprflow purpose:** Added specifically so wsprflow can submit dictated text
directly to a supported field without clipboard involvement. This avoids Firefox
GTK cancelling a private clipboard read when the real offer is restored. See the
[wsprflow feature overview](wsprflow.md) for related Niri and Smithay changes.

A dictation integration can submit new text directly to the native Wayland field
whose live surrounding-text revision it holds. No clipboard offer, selection
replacement, paste shortcut, synthetic key or delete-surrounding-text request is
generated by Niri. The receiving widget applies its ordinary text-input commit
semantics, which can replace its current selection or composition.

Keep a dedicated [text context](text-input-context.md) connection open. Refocus
the original window and read its current context, then send on another connection:

```json
{"CommitText":{"id":12,"text":" this continues.","context_revision":7}}
```

New text must contain 1–4000 UTF-8 bytes, within a bounded Wayland message. A
revision is mandatory. Niri refuses invalid length, held keys/modifiers, keyboard
grabs, locked/non-layout focus, a bound external input method, and stale/expired
context **before** sending any text. It never focuses a different window itself.
Window, exact surface, live text-input object, field activation, text, caret,
anchor and content type must still match the snapshot. Existing field text is
not rewritten. A stale revision uses the same error as conditional private paste.

Niri submits only `commit_string` and matching `done` to the active text input,
then consumes the revision so it cannot be reused for a duplicate insertion.
The reply is:

```json
{"Ok":{"TextInputCommitted":{"id":12}}}
```

This acknowledges protocol submission, not application acceptance. A lost reply
is uncertain and must not cause automatic retry or a private-paste/clipboard
fallback. Submission already queued cannot be recalled by closing the requesting
connection. Clients needing more text should review and send smaller drafts;
Niri does not split a commit into several implicit editing operations.

Ordinary clipboard/primary ownership, bytes, MIME types and data-control history
are completely untouched. Transcript contents are redacted from Debug and CLI
`--print-request`; supply text through structured IPC, not process arguments.
Unsupported fields use the existing private-paste capability only when the
integration has not attempted a text-input commit.

Keep protocol tests asserting exact Unicode commit text, matching done, single-use
revision, no preedit/delete and no private offer creation. Keep size/stale refusal,
JSON/redaction coverage, and off-screen Firefox/Chromium input, textarea and
contenteditable acceptance with a preexisting PNG clipboard and cliphist watcher.
The context observation/selection limits and client trust boundary still apply.
